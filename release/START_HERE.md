# Local Component Workbench 0.1.0-rc.1

Open **app/Workbench.cmd** to start the guided menu. The existing local Python installation is detected automatically on this machine. Choose Check setup, then run the Python baseline or the C# regression check. Detailed commands are in app/START_HERE.md.

The workbench contains 393 catalog entries: 377 core and 16 supporting. Three bounded fixture capabilities are runnable through two adapters. The remaining records stay visible with their limitations. A successful regression diagnostic correctly reports that the flawed candidate was rejected.

Run history is stored outside app/, by default in Local_Component_Workbench_State beside app/. Keep that state folder when removing or replacing the application. Use --state to select another folder. The generated report command prints the HTML report location.

The shared foundation and workbench have separate manifests and versions. The coding-agent platform and research toolkit are separate deferred products. All 9,364 original files remain unchanged. Historical scientific failures and all eight original G2 failures are preserved.

This package passed the shared foundation's 34 security/recovery tests and 72 integrated scenarios, plus 13 workbench acceptance groups using 27 real CLI commands and 14 Windows launcher/removal checks. The exact final application was then run again to produce the example report.

See EXECUTION_REPORT.md for scope and evidence, app/KNOWN-LIMITATIONS.md for limits, and app/ROLLBACK.md for safe removal. This is a private local prerelease, with no external publication or deployment.
